# 打包发布规则

适用：任何 Release / 便携包 / 交付 ZIP 的构建与验证。

## 目标定义

Release = **冻结基线版本中属于本次发布合同、且无获批变更的功能集合 + 本次批准修改**，不是"测试过程中跑通的功能子集"，也不意味着恢复所有历史功能或修复所有既有缺陷。

禁止只复制测试期间访问过的资源作为发布包。

## 依赖闭包

存在 lazy import、动态 chunk、插件、CSS `url()`、字体、图片等资源时，必须验证**完整依赖闭包**。开放式依赖（运行时任意第三方插件、用户自定义远端资源）写明支持边界，不声称扫描少数页面即"证明完整"。静态资料 ZIP 不含服务与动态资源时，相应后台/动态检查不适用，跳过即可，不为满足模板搭建不存在的运行环境。

发布前至少检查：

- 所有本地静态依赖可解析
- 所有 lazy chunk 存在
- 本地 HTTP 请求无 404
- 用户核心真实工作流可打开
- Release ZIP 解压到全新目录后再次验证

## 测试覆盖

发布测试必须覆盖用户真正依赖的功能，不能只覆盖本次修改点。

编辑器型项目不能只验证"页面能打开、保存正常"，还必须验证主要编辑器本身能够加载。

## 后台进程

不得假定 Agent 执行环境与用户真实桌面环境具有相同的进程生命周期。

后台服务在 Agent 执行结束时被外部直接终止、且无正常 exit / error 事件时，候选原因包括：

- Agent sandbox
- Windows Job Object
- 父进程树清理
- 执行器生命周期限制

先记录进程、父进程、可获得的退出证据与环境差异；证据不足时把原因写成假设，不凭现象锁定单一根因。

不得为了让沙箱中的后台进程存活而擅自修改正式产品的进程模型。

此类情况标记 `REQUIRES_MANUAL_OUT_OF_AGENT_VALIDATION`，由用户在正常桌面环境手动启动验证。该标记是验证缺项，不等于发布通过：若持续运行属必需验收，未测前整体结局不得报 `PASS`，可先交付包、说明缺项并保留整体阻断；用户只要候选包时按该阶段范围报告。

## 环境隔离

- 测试使用副本，原件只读
- 测试 fixture 的收益不得归到正式实现上
- 开发机 / Headless Benchmark 的 FPS 不得宣称为用户真机 FPS
